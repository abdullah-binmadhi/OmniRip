## [Unreleased]

### Added

- **PLAYER dynamic per-preset visual system (formerly Full Vision; docs/research/player-art-direction.md):** the studio is renamed end to end (`player_studio.py`, `player_designs.py`, `Player*` symbols, `plr-*` ids, `omnirip-player` console script) and every one of the 23 built-in pages now carries its own authored page grammar — control rail and axis, companion/dock/motif slots, frame glyphs, border roles, motion signature, and a per-family transport vocabulary (`keys`, `brackets`, `pills`, `plaques`, `knobs`, `kiosk`, `toggles`, `lcd`) resolved at runtime by `player_layout.py`; user-saved layouts keep the legacy chrome through the `LEGACY_*` maps. A terminal render-fidelity engine (`render_fidelity.py`) spans octant (opt-in), sextant (default), quadrant, half-block, braille, and ASCII with Unicode-name pattern tables, nearest-pattern shape matching, dithering, and cell deltas; a living companion (`companion.py`) derives determined moods and BPM from the audio stream, renders 23 scene recipes, speaks preset-voiced dialogue, and tracks a cheer meter; and a single palette bus drives chrome, cards, companion, and scene from the active Stitch theme. Reskin acceptance tests assert unique structural, visual, and companion signatures per preset at 100×30 and 200×50. `ui.visual_fidelity` and `ui.reduced_motion` (documented in `config.example.toml` and the README) tune the render ladder and motion accessibility; `reduced_motion` freezes the companion scene, disables blink/marquee/scanline, and renders portraits statically.
- **Lossless enhanced masters (docs/01 D37, M19):** the Deck's export menu gains **Enhanced WAV** and **Enhanced FLAC** beside the default 320 kbps MP3. Both formats run the exact same render chain as the MP3 (`export_enhanced_lossless` shares `_render_enhanced`), so EQ, preset and genre colour can never diverge; output is **24-bit PCM / 48 kHz** — the engine's native rate, no resample — with container-appropriate provenance (Vorbis comments for FLAC, an ID3 chunk for WAV). An unsupported format raises instead of writing something else, and the MP3 stays the one-press default.
- **Genre-aware tasteful mastering (docs/01 D38, M20):** the Deck gains a `GENRE` control (`Auto` / `Neutral` / `Mix…` / 20 profiles) with **Subtle / Balanced / Bold** intensity, backed by a new `analysis/enhancement/genres.py` engine. Profiles are capped (≤4 bands, ≤2.5 dB, at least six of ten bands untouched), mixes of up to six genres are averaged so conflicting intentions cancel instead of stacking, and detection is automatic — local genre tags first (only genre-ish keys: titles/comments can never masquerade), then a background MusicBrainz refinement while the mode is `Auto`, never overriding a manual pick. The composed curve layers on top of the user's master EQ and feeds playback, the ENH cache tag, MP3/WAV/FLAC exports and the Repair master; provenance records `GENRE`, `GENRE_MIX` and `GENRE_INTENSITY`, and a Deck recipe line states the moves, intensity and limiter in plain language.

- **Repeating visuals in Dashboard Presets (docs/01 D39):** Previously, while presets enforced 10 unique *renderer families* internally, the dashboard UI suffered from identical repeated visuals globally because the pool of renderers was too small. We re-assigned all 200 preset dashboard panels to pull from a strict pool of 200 fully unique engines (drawing from `catalog_100` and `catalog_200`), guaranteeing 100% uniqueness across the entire application's layout store without weakening per-preset constraints.
- **REPAIR page rendered nothing (M18 follow-up):** `RepairPanel` is a bare `Widget` with no CSS, so Textual computed **height 0** and clipped every child — the page showed an empty box even though the card, buttons and ranges all existed (tests asserted `styles.display`/text but never sizes, so it shipped). New glyphs (`◈ 𝄢 ⌂ ⌖`) match the app's existing symbol vocabulary. Regression tests now assert non-zero panel/card/button regions at both panel and workbench level.

### Added

- **Neural model registry reality check (docs/01 D34, docs/10 M10):** every registry checkpoint was audited against what the providers can actually load, and the three that could not load were fixed or retired.
  - **FlashSR is now the real pipeline.** `FlashSRProvider` runs the upstream one-step distilled-diffusion model — student LDM + VAE + SR vocoder — resampling to 48 kHz, processing exactly-245,760-sample (5.12 s) windows with equal-power overlap-add, extracting only the band above `max(cutoff, 16 kHz)` and resampling back. Measured 31 s per window on CPU (MPS used when available). The three weight files are registry entries (`flashsr_ldm` 1.0 GB, `flashsr_vae` 1.7 GB, `flashsr` 0.6 GB); because the upstream redistribution packages badly (`find_packages()` with namespace subpackages), the runtime snapshots just the inference code (2.8 MB) into the model cache and imports from there, wrapping `torch.load` with `map_location="cpu"` while the CUDA-saved checkpoints load. Any missing weight, snapshot failure or inference error degrades to the harmonic air-band generator — never a failed run.
  - **NVSR's registry slot is retired.** `haoheliu/wellsolve…/basic.pth` is the AudioSR latent-diffusion bundle (verified by state-dict keys), not a one-shot SR model, and upstream `audiosr` pins `numpy<=1.23.5` / `transformers==4.30.2`, so it cannot be installed beside this project. `NVSRProvider` keeps its name and preset wiring but is now honestly the harmonic high-band engine (Torch MPS/CPU, NumPy fallback), and the dead `torch.jit.load` path and 5.8 GB download spec are gone.
  - **Neural de-reverb wired.** `anvuew/dereverb_bs_roformer` (51 M-param state_dict, no modeling code upstream) now runs through the vendored MSST BS-RoFormer architecture (GPL-3.0, `src/harvester/vendor/msst/`, attributed and excluded from lint) in 10 s windows at 50 % overlap; `_apply_dereverb_isolation` blends the neural dry vocal by the existing intensity knob and keeps the spectral kurtosis engine as fallback. Verified on the real checkpoint: loads in 1 s, 2 s stereo in 2.1 s.
  - **Dependencies:** `restore` extra gains `transformers`, `beartype`, `rotary_embedding_torch`; new `flashsr` extra (librosa, matplotlib, psutil, pyyaml, tqdm); the workbench model registry now reports the four engines and FlashSR's three files.
  - **Tests:** new `tests/test_dereverb.py` (7 cases: chunk math, vendored architecture forward, intensity blending, spectral fallback, identity) plus a mocked FlashSR neural-path case and updated registry/provider tests that stay hermetic against an empty model cache.

- **Spectral anti-fraud v2 (docs/16, implements docs/04 §9, D32):** the four promised rules are now real, all FRAUD-only and all evaluated after the v1 rules, so no existing verdict changes except the documented `up96_void` upgrade (INCONCLUSIVE → FRAUD).
  - **Hi-res void (R1):** a ≥ 88.2 kHz claim whose energy above 22.05 kHz sits within 6 dB of FLOOR **and** ≥ 20 dB below BASE is an upsample. The second condition is deliberate: on flat material the 10th-percentile FLOOR sits at the content level, so the literal §9.1 test would call honest hi-res audio a void.
  - **Fake bit depth (R2):** a ≥ 24-bit claim whose content's low byte is empty in ≥ 98 % of a ≥ 1 s native-rate excerpt. Measured against real ffmpeg output: the informative byte is bits 8–15 (ffmpeg left-aligns every depth into `s32le`, so bits 0–7 are always zero), the statistic is a *share* rather than a bitwise OR (one clipped sample would dominate a union), saturated samples are dropped (a clipped master pins that byte to 0xFF), and the decode keeps the file's own rate and channel layout (`-ac 2` on mono fabricates a full-range low byte; `-ac 1` on stereo leaks a 17th bit through the downmix).
  - **SBR / tonal artifacts (R3):** ≥ 3 bands above the passband top + 1 kHz that beat their four neighbours by ≥ 6 dB and sit ≥ FLOOR + 6 dB — content above the encoder's own passband is injected, not recorded.
  - **Stereo asymmetry (R4):** the side channel must carry energy within 20 dB of the mid (a near-mono mix abstains); the lower of the two v1 cutoffs must then be ≤ 19 kHz, differ from the other by ≥ 2 kHz and be steep (S ≥ 20 dB/kHz).
  - **Wiring:** phase 4 decodes the excerpt as **stereo** f32 and splits mid/side (`mid_side`) instead of a mono downmix, which would average the asymmetry away; the native-rate s32 decode runs only for ≥ 24-bit claims and is best-effort (a failure leaves the bit rule to abstain instead of sinking a verdict the spectral rules reached). `FfmpegService` gains `probe_bit_depth` and `decode_s32`, `decode_f32` gains `channels`, `probe_audio_info` reports `bits`.
  - **Tests:** `tests/test_spectral_v2.py` (17 cases: every rule, its controls — honest hi-res, symmetric stereo, quiet side, no-birdie brick wall — the helpers, and one ffmpeg-backed end-to-end bit-depth case), three new phase-4 wiring cases, and the `up96_void` fixture fix: it never actually contained a void (the old recipe zero-padded the *time* domain, which reinterprets 44.1 kHz samples at 88.2 kHz and fills the top of the band; its INCONCLUSIVE came from FLOOR sitting at content level). No new dependencies.

### Changed

- **Layer Studio true zoom-in (docs/12 §1, docs/01 D33 M2):** the analysis now also computes a fine int8 min/max envelope per lane at 25 ms (`FINE_BUCKET_S = 0.025`, 40 points/s, ~48 KB per 10-minute lane) — one file load, vectorized. It is shipped to the detached terminal as a companion `.{stem}.layer_sidecar.peaks.npz` written atomically beside the JSON with the same source fingerprint, so the edit-plan channel stays small; `read_peaks` attaches it on terminal load/reload and silently falls back to the per-second envelope for a missing, legacy, corrupt, version-mismatched or fingerprint-mismatched file. The widget's zoom ladder gains `0.5 / 0.25 / 0.1 s per column` with real sub-second detail (a 0.5 s transient now renders in one column instead of smearing across its whole second), and 2-row lanes mirror the fine min/max around the lane centre (top row grows upward from the maximum, bottom row downward from the minimum). Workbench writes peaks wherever it writes the sidecar (terminal open, post-commit refresh). Tests: `tests/test_layer_fine.py` (9 cases) plus a terminal-channel test.
- **Layer Studio rebuilt as a tui-wave-style continuous editor (docs/12 §2.2/§4, docs/01 D33):** the detached terminal's grid no longer draws three-band braille rows with an unbroken `─` line through silence. Each lane is now one continuous Braille strip from its per-second peak envelope, and silence renders blank — strips read as disconnected clips, not endless lines. Interaction follows tui-wave: `←/→` move the cursor second, `shift+←/→` extend a region selection, `+/-` step the zoom ladder (16 → 0.1 s per column, anchored on the cursor), `v` toggles 1-row/2-row lane strips, `x` clears the selection, and an op key (`m/b/s/u/p/h/a/c/g/t/r`) applies to **every second in the region** (or the cursor second when there is none). **Click accuracy is fixed:** render and hit-testing now share one layout contract (24-column header cards, 3 ruler rows, lane height) and clicks map through Textual's content-offset API, so padding no longer shifts x, the separator/ruler no longer clamp to lane 0, and the previous off-by-one that made the third row of a lane select the next lane is gone; mute/solo zones (columns 1–3 / 5–7) match what is drawn. The terminal status line shows zoom, lane height and the selected region, and the studio takes focus so the key map works without clicking it first.
- **Song-driven dynamic lanes:** the fixed four rows (vocals / bass / drums / other) are replaced by the lanes the song actually has. `analysis/enhancement/dynamic_layers.py` splits a family into disjoint child lanes — `drums → kick / snare / hats`, `bass → sub_bass / bass` — using the zero-phase complementary crossover with a narrow transition, and keeps a split only when every child clears the presence gate (active-second ratio ≥ 5 %, mean RMS ≥ -50 dBFS); otherwise the parent row survives whole. Children partition the parent exactly, so mix reconstruction keeps its -40 dBFS budget. Extra neural sources (e.g. `guitar` / `piano` from a 6-source model) become lanes automatically, so a track can render 4–8+ rows. The `LAYERS` status line reports the detected layout (`kick/snare/hats · bass → sub_bass/bass`).
- **Lane rows render only in the detached layer terminal:** the workbench `LAYERS` page no longer embeds the grid or the tool palette, so the timeline gets the full width of its own terminal window.
- **The detached terminal is now genuinely connected to OmniRip playback:** a new transport channel (`layer_sidecar.transport.json`, atomic writes) publishes the playhead / playing state / duration from the main app — which owns audio — at 5 Hz and carries the terminal's seek/play requests back. The terminal follows that playhead (the grid moves with the song), re-issues unanswered requests until the main app confirms them, and reloads lanes whenever the sidecar changes. Fixes the detached page sitting still while a track played in OmniRip.
- **AcoustID `meta` is posted as a repeated form field** (`meta=recordings&meta=releases&…`) instead of one `+`-joined string, which URL-encoded to a literal `+` and silently returned results with no recordings block (no title/artist resolution). Verified against the live API on a real track (title + artist + MusicBrainz recording id + 0.98 confidence).
- **Local secret file for API keys:** a gitignored `.env` (or `OMNIRIP_ENV_FILE`) is loaded into the process environment at startup, so GUI launches that do not inherit shell exports still find `ACOUSTID_API_KEY`; real environment variables still win and values are never logged or written back. `.env.example` documents the keys.
